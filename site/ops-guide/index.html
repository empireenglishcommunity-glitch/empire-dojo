🏛️ الرسالة والرؤية

🎯 الرسالة / Mission

مساعدة المتعلّم العربي على بناء لغة إنجليزية حقيقية وواثقة وقابلة للاستخدام — عبر ممارسة يومية بسيطة، ومتابعة صادقة، ومجتمع داعم.

🌅 الرؤية / Vision

مجتمع من المتعلّمين يحضرون كل يوم، يدعمون بعضهم، ويحوّلون الجهد الثابت إلى طلاقة — حيث يكون التقدّم شخصياً ومُتتبَّعاً ويُحتفى به.

القيم التشغيلية: صفر إزعاج للطلاب • أي تغيير عبر PR يوافق عليه المالك • اختبارات خضراء قبل الدفع • نسخ احتياطية خارج الموقع • لا حذف لتاريخ Git. Common Sense First 🏛️

🗺️ خريطة المنظومة

ثلاث مستودعات تحت منظّمة empireenglishcommunity-glitch:

🤖 empire-nexus القلب / Backend

بوت Discord التعليمي + بوت التليجرام للإدارة (Empire Ops) + الـ API والخادم. يعمل داخل حاوية empire-english-bot على الخادم (Docker Compose). يخدم bot.empireenglish.online (التغييرات، الجلسات، التقدّم).

📚 empire-dojo صفحة التمرين / Frontend

منصة التمرين practice.empireenglish.online على Cloudflare Pages (مشروع empire-practice). تتضمّن بوابة الحافة functions/_middleware.js ودليل الطالب /guide ودليل الإدارة /ops-guide (هذه الصفحة).

📖 empire-chronicle الذاكرة / Docs

التوثيق، استمرارية الجلسات، الخطط، عمليات التدقيق، ونظام ذاكرة الذكاء الاصطناعي. المرجع التاريخي للقرارات والإجراءات.

🧭 رحلة الطالب (ملخّص)

1
الربط: الطالب يكتب !link في Discord → كود لمرة واحدة (15 دقيقة) → يفتح practice.empireenglish.online → جلسة 60 يوماً.
2
المهام اليومية (7): 5 على المنصة (Accent, Shadowing, Speaking = تسجيل؛ Listening, Vocabulary = تلقائي) + 2 على Discord (Writing, Community).
3
التقدّم: عدّاد موثوق من الخادم؛ إكمال المهام الخمس = يوم أخضر. تزامن عبر الأجهزة.
4
الإتقان + المراجعة: ترقية المستويات (Bronze→Diamond) + مراجعة الكلمات السابقة عبر نظام التكرار المتباعد (SRS).
5
الاختبار الأسبوعي (Itqan): نهاية كل أسبوع يثبت الطالب إتقانه؛ النجاح يمنحه الإتقان + قناة الأبطال + الشهادة. المهام اليومية تبقى مفتوحة دائمًا (لا تجميد). التفاصيل في بطاقة Itqan أدناه.

🚩 أعلام الميزات (Feature Flags) — المرجع الكامل

كل ميزة في النظام لها «عَلَم» يقدر يشغّلها/يطفيها فورًا بدون إعادة نشر — ده مفتاح الأمان والطوارئ. 🟢 = مُفعّل افتراضيًا · 🟠 = مُطفأ افتراضيًا.

التحكّم: Discord !flag list (يعرض الكل بحالتها) · !flag enable <name> / !flag disable <name> (للجميع) · !flag beta <name> @user… (لأفراد محدّدين). تليجرام: /flag · /flag <name> on|off.

النظام مبني كمبادرات مستقلّة، كل واحدة تتحكّم فيها أعلامها (راجع قسم الأعلام). ملخّص وظيفة كل واحدة:

🧰 وضع الصيانة

لما تحتاج توقف الخدمة مؤقتًا (نشر كبير، صيانة) بدون ما تكسر ثقة الطلاب أو سلاسلهم:

!maintenance start [soft|hard] [minutes] [reason]
يبدأ الصيانة: soft = تحذير لطيف مع استمرار العمل؛ hard = إيقاف فعلي. يُخطر الطلاب تلقائيًا.
!maintenance end [what's new]
إنهاء الصيانة + إعلان العودة (وممكن تذكر الجديد).
/maintenance (تليجرام)
نفس التحكّم من هاتفك.
🔥 حماية السلاسل: أيام الصيانة تُسجَّل ولا تكسر سلسلة أي طالب — اليوم يُتجاوز تلقائيًا في حساب السلسلة.

📝 الاختبار الأسبوعي (Itqan) — التحكّم والأوامر

اختبار نهاية الأسبوع يثبت أن الطالب أتقن محتوى الأسبوع فعلاً. يظهر في تقويمه بعد إنهاء أيام الأسبوع، ويقيس المهارات الخمسة، ويعطي نتيجة على بُعدين: Consistency (الالتزام اليومي) + Mastery (الاختبار).

🚩 العَلَمان (Feature Flags)

itqan_weekly_assessment
يُشغّل ميزة الاختبار الأسبوعي بالكامل (الصفحة + الأوامر + الإشعارات + التقارير).
itqan_progression_gate
ناعم (منذ 2026-07-28): لم يعُد يُجمّد المهام اليومية إطلاقًا — التمرين اليومي مفتوح دائمًا حسب التاريخ لحماية العادة اليومية. يبقى كمعلومة إرشادية (allowed_week) لخريطة التقدّم؛ ومنع «التخطّي الأجوف» مضمون لأن الإتقان + قناة الأبطال + الشهادة كلها تتطلّب اجتياز اختبار كل أسبوع فعليًا. (كان يُجمّد أيام الأسابيع المتقدّمة — أُزيل هذا التجميد.)
التحكّم: في Discord !flag enable <name> / !flag disable <name> (للجميع) أو !flag beta <name> @students… (تجربة مصغّرة). في تليجرام /flag <name> on|off. !flag وحده يعرض كل الأعلام وحالتها.
⏳ محاولة انتهى وقتها قبل أي إجابة تُلغى تلقائيًا (لا نتيجة، لا رسوب، لا فترة انتظار) — فلن ترى «رسوبًا وهميًا» من طالب فتح الاختبار وتركه. كذلك تنبيه «غير نشِط» يُرسَل مرة واحدة يوميًا كحدّ أقصى لكل طالب (بدل كل ساعة سابقًا).

🛠️ أوامر الإدارة (Discord)

!itqan [L0-L3]
تقرير الإتقان الأسبوعي (نظرة عامة لكل مستوى).
!itqan-due [L0-L3]
التقرير الشامل: مَن عليه اختبار مستحقّ ولم يؤدِّه، ومَن أنهى/رسب/نجح، والأيام المتبقّية. هذا هو تقرير «مَن لم يختبر بعد».

تجاوز يدوي: اعتماد إتقان الأسبوع للطالب + الاحتفاء به تلقائياً (DM + قناة الأبطال + شهادة عند إتمام المستوى).
!itqan-reset @user <week>
مسح محاولات الطالب لأسبوع معيّن ليعيد الاختبار من جديد.

🔎 مراجعة المحاولات المعلّمة + الضبط

الفلسفة: النجاح الواضح يُحتفى به فوراً (تلقائياً، بدون تدخّلك)، والرسوب الواضح يذهب للطالب كرسالة خاصة داعمة بقائمة المراجعة (بدون فضيحة). يصلك تنبيه فقط عندما تحتاج المحاولة عيناً بشرية.

متى يصلني تنبيه؟

عندما لا تنجح المحاولة و(وُجد خطأ يحتاج تقدير الذكاء الاصطناعي أو كانت النتيجة على حافّة النجاح ضمن ±5 نقاط). التنبيه يصل إلى تليجرام الإدارة (وسجلّ تنبيهات Ops) ويحتوي:

•
اسم الطالب + المستوى + الأسبوع + رقم المحاولة.
•
نسبتَي Mastery وConsistency + سبب التعليم.
•
الأوامر جاهزة للنسخ لهذا الطالب تحديداً (!itqan-review / !itqan-pass / !itqan-reset) — لا حاجة لحفظ أي أمر.

ماذا أفعل (السيناريو)

1
شغّل !itqan-review <attempt_id> (أو /itqan-review واختر الطالب). يصلك ملف منظّم: ماذا كان خطأ في كل مهارة، وما يحتاج انتباهاً، وما الذي تقوله للطالب — إرشاد كامل.
2
استمع إلى التسجيلات الصوتية المرفقة (نطق/تحدّث) لتحكم بنفسك على الأداء الحقيقي.
3
قرارك: إمّا !itqan-pass @user <week> (يستحقّ النجاح → احتفاء تلقائي)، أو اتركه يعيد المحاولة / !itqan-reset @user <week> لإتاحة إعادة نظيفة.
🎧 الاحتفاظ بالتسجيلات: تُحفظ صوتيات المحاولات 14 يوماً للمالك فقط ثم تُمسح تلقائياً يومياً. بعد النافذة تكون المراجعة نصّية فقط.

⚙️ ضبط الإعدادات (متقدّم — على مستوى قاعدة البيانات)

القيم الافتراضية تعمل جيداً؛ عدّلها فقط عند الحاجة عبر docker exec:

docker exec empire-english-bot python3 -c \
 "import src.database as d; d.set_itqan_config('itqan_mastery_pass_pct', 70)"
itqan_mastery_pass_pct
درجة الاختبار اللازمة للنجاح — الافتراضي 70.
itqan_consistency_pass_pct
درجة الالتزام اليومي اللازمة — الافتراضي 70.
itqan_distinction_pct
درجة الإتقان لوسام ⭐ التميّز — الافتراضي 90.
itqan_retake_cooldown_min
دقائق الانتظار قبل إعادة المحاولة — الافتراضي 720 (12 ساعة).
itqan_spiral_recent_weight
نسبة أسئلة الأسبوع الأحدث (الباقي مراجعة حلزونية) — الافتراضي 0.65.
itqan_time_limit_min
الحدّ الزمني الكلّي للاختبار بالدقائق — الافتراضي 15.
هامش الحافّة للتعليم (borderline margin) ثابت عند ±5 نقاط حول خط النجاح. أي مفتاح غير معروف يُرفض تلقائياً لمنع الأخطاء الإملائية.

🗣️ تقييم النطق (Nutq) — «Grade my best read»

ميزة تُعطي الطالب درجة نطق دقيقة واحدة في اليوم على مهمة Shadowing فقط. الفلسفة: التمرين حرّ بلا أرقام، والدرجة الرسمية دقيقة وباختيار الطالب — فلا يرى المبتدئ رقماً «غير عادل» من محرّك ضعيف.

كيف تعمل للطالب

1
يسجّل ويضغط 📤 Send to Discord كالمعتاد → يظهر له تشجيع بلا رقم (يقدر يعيد قد ما يحب، وكل إعادة ترفع الـ tier).
2
لمّا يرضى عن محاولته يضغط 🏅 Grade my best read — مرة واحدة في اليوم — فيحصل على درجته الرسمية الدقيقة (محرّك Azure السحابي) مع الكلمات التي يركّز عليها.
3
تصلك نسخة من الدرجة الرسمية في قناة التغذية الراجعة للمعلّم (خاصّة بك وحدك) — لا شيء عامّ يُحرج المبتدئين.

لماذا هكذا (التكلفة + الجودة)

المحرّك الدقيق (Azure) له طبقة مجانية محدودة؛ لذلك نحدّه بـ درجة رسمية واحدة لكل طالب يومياً، والتمرين/الإعادة يستخدم المحرّك المجاني المستضاف ذاتياً. هكذا نتوسّع لعشرات الطلاب مجاناً دون كسر التجربة. الحدّ صارم ومضمون تقنياً حتى مع الضغط المتزامن؛ ولو نفدت الحصة الشهرية يتحوّل تلقائياً للمحرّك المجاني.

🎛️ أوامر التحكّم — /nutq (تليجرام + Discord Slash)

/nutq status
الحالة: مَن لديه الميزة + الحدّ اليومي لكل طالب. ملاحظة: في تليجرام يكفي /nutq وحده؛ في Discord اكتب /nutq status (لأن /nutq مجموعة أوامر، فلا تعمل وحدها).
/nutq grant <اسم/id>
إعطاء الميزة لطالب — يبدأ تلقائياً بـ 1 درجة/يوم (لا حاجة لضبط cap).
/nutq revoke <اسم/id>
سحب الميزة من طالب.
/nutq everyone · /nutq off
تشغيل للجميع · إيقاف للجميع.
/nutq cap <اسم/id> <عدد>
تغيير عدد الدرجات الرسمية/اليوم لطالب معيّن (الافتراضي 1) — اختياري، للاستثناءات فقط.
/nutq capreset <اسم/id>
إرجاع الطالب للحدّ الافتراضي (1/يوم). في تليجرام بدلاً منه: /nutq cap <اسم/id> default.
📟 في تليجرام اكتب الأوامر كما هي (و/nutq وحده = الحالة). في Discord استخدم أوامر الـ Slash من قناة #admin-commands (الـ ! لا يعمل هناك) — واختر الطالب بالاسم من القائمة تلقائياً: /nutq grant, /nutq cap, /nutq capreset…
✅ الاستخدام الأساسي: فقط /nutq grant <الطالب> — وبكده ياخد زر 🏅 ودرجة واحدة يومياً. الـ cap اختياري للاستثناءات فقط.
🔒 أمان التحكّم بمن (WHO): إزالة آخر طالب من القائمة تُطفئ الميزة تلقائياً (حتى لا تُفتح للجميع بالخطأ). ولو كانت «للجميع» لا يمكن استثناء فرد واحد — استخدم off أو امنح أفراداً محدّدين.

⚖️ الحوكمة — إعادة ضبط سجلّ الطالب

هذا أهمّ سير عمل حسّاس. القاعدة: لا حذف بلا موافقة موثّقة، ولا تنفيذ بلا موافقتك.

1
الطلب: الطالب !resetme (أو الإدارة !reset-student).
2
الموافقة الموثّقة (Consent): تُسجَّل موافقة الطالب في سجلّ الموافقات — دليل دائم أن الحذف تمّ بطلبه.
3
لقطة (Snapshot): يُؤخذ نسخ كامل لسجلّ الطالب قبل أي تغيير (يتيح الاستعادة).
4
موافقة المالك: يدخل الطلب قائمة الانتظار وتصلك إشعارات؛ توافق عبر /approve (تليجرام) أو !approve-reset (Discord).
5
التنفيذ: بعد موافقتك تُنفَّذ إعادة الضبط. الاستعادة ممكنة عبر !restore-student من اللقطة عند الحاجة.

🚀 دليل التشغيل (Runbook)

⚠️ كل التغييرات عبر PR يوافق عليها المالك. الاختبارات يجب أن تكون خضراء قبل الدفع. لا دفع مباشر إلى main. لا إعادة كتابة لتاريخ Git.

1) نشر البوت (empire-nexus)

ssh -i <deploy_key> root@<SERVER_IP> \
  "cd /opt/empire-english-bot && git pull --ff-only && docker compose up -d --build"

2) نشر صفحة التمرين (empire-dojo)

cd empire-dojo
CLOUDFLARE_ACCOUNT_ID=<account_id> CLOUDFLARE_API_TOKEN=<token> \
  npx wrangler pages deploy site --project-name=empire-practice --branch=main

3) الاختبارات

cd empire-nexus/bots/discord-learning-bot
python3.12 -m pytest tests/ -q   # يجب أن تمرّ كلها قبل أي دفع

4) مطابقة/مصالحة البيانات (Reconcile)

docker exec empire-english-bot python3 -m src.reconcile

5) النسخ الاحتياطي والاستعادة

•
محلي: نسخة يومية على الخادم (cron).
•
خارج الموقع (R2): رفع تلقائي إلى Cloudflare R2 — bucket empire-english-backups عبر remote r2 (cron 03:20).
•
تنبيه الحداثة: فحص يومي (cron 04:00) — لو غابت النسخة أو تقادمت، يصلك تنبيه على تليجرام الإدارة.
•
اختبار الاستعادة: جُرِّب واستُعيدت النسخة بنجاح؛ كرّر الاختبار دورياً.
🔑 كل الأسرار (مفاتيح النشر، رموز Cloudflare، مفاتيح R2) تُحفظ خارج المستودعات (على الخادم / أسرار المنصة) — لا تُكتب في أي صفحة أو كود.
⚠️ دمج PR ≠ نشر مباشر لصفحة التمرين. بعد دمج أي PR يمسّ site/ لازم تشغّل أمر النشر (خطوة 2) — مفيش نشر تلقائي لـ Cloudflare Pages. تأكّد إن الصفحة الحيّة اتحدّثت فعلاً (مش مجرّد نجاح الأمر).
